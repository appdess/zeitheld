# Development workflow

- For routine maintainer development, iterate, test, commit and build locally.
- Do not open pull requests or push each intermediate change unless requested.
- After the result is validated, publish the final source in one consolidated push.
- Contributor submissions use pull requests. Keep their CI/review support available.
- Before a launch or binary release, enable and verify the stricter review and release controls in SECURITY.md and CONTRIBUTING.md.
- Keep credentials, signing material, real child data and local test artifacts out of commits. Paid API tests remain explicitly opt-in.
